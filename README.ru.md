# git-lineage

[![CI](https://github.com/bronekot/git-lineage/actions/workflows/ci.yml/badge.svg)](https://github.com/bronekot/git-lineage/actions/workflows/ci.yml) [![crates.io](https://img.shields.io/crates/v/git-lineage.svg)](https://crates.io/crates/git-lineage) [![Лицензия: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

[English](README.md) · Русский

`git-lineage` — кроссплатформенная консольная утилита на Rust для построения компактного семантического дерева веток Git. Вместо полного графа коммитов она показывает логических родителей, опережение и отставание, расхождение локальных и upstream-веток, сравнение соседних веток и синхронизированные upstream-ветки.

Без пояснений команда `git lineage --summary none` выводит примерно такой отчёт:

```text
Данные из origin получены; граф веток:

main
├─ dev (текущая)                 +8 от main
│  └─ origin/dev                 +1 от dev
│     └─ commands-fun            +12 от origin/dev
└─ web-ui                        +13 от main
```

## Установка

Рекомендуемая установка с crates.io через Cargo; флаг `--locked` использует версии зависимостей, проверенные для релиза:

```console
cargo install git-lineage --locked
```

Cargo устанавливает `git-lineage` в подкаталог `bin` выбранного корневого каталога. При стандартных настройках это `$CARGO_HOME/bin` — обычно `~/.cargo/bin`, а в Windows — `%USERPROFILE%\.cargo\bin`. Этот каталог должен находиться в `PATH`: Git обнаруживает только те внешние команды `git-*`, которые доступны через `PATH`.

После установки проверьте оба варианта запуска:

```console
git-lineage --version
git lineage --version
```

Если `git-lineage` работает, а `git lineage` — нет, проверьте наличие каталога с `git-lineage` в `PATH` и перезапустите терминал.

Чтобы установить текущую версию для разработки из ветки `main`, а не последний релиз с crates.io:

```console
cargo install --git https://github.com/bronekot/git-lineage --locked
```

В разделе [GitHub Releases](https://github.com/bronekot/git-lineage/releases) доступны готовые архивы для следующих платформ:

- Windows x86_64: `x86_64-pc-windows-msvc`
- Linux x86_64: `x86_64-unknown-linux-musl`
- macOS Apple Silicon: `aarch64-apple-darwin`

После распаковки переместите исполняемый файл `git-lineage` или содержащий его каталог в один из каталогов `PATH`.

## Использование

При стандартных настройках перед построением отчёта выполняется `git fetch --prune --quiet -- origin`. Чтобы использовать уже сохранённые в локальном репозитории ссылки:

```console
git lineage --no-fetch
git lineage --offline
```

Заголовок отчёта сообщает, были ли получены данные из удалённого репозитория, пропущен ли `git fetch` или после его ошибки использованы сохранённые данные.

Основные команды:

| Команда | Назначение |
| --- | --- |
| `git lineage` | Построить стандартный отчёт |
| `git lineage init` | Создать `.git-lineage.toml` |
| `git lineage discover` | Вывести полную предлагаемую TOML-конфигурацию |
| `git lineage discover --write` | Перезаписать `.git-lineage.toml`, добавив найденные связи |
| `git lineage parent <CHILD> <PARENT>` | Установить логического родителя |
| `git lineage parent <CHILD> --unset` | Удалить логического родителя |
| `git lineage check` | Проверить ссылки, соответствие настроенных родителей истории Git, выбранный удалённый репозиторий и циклы |
| `git lineage language [LANGUAGE]` | Показать или сохранить язык интерфейса; поддерживаются `en` и `ru` |

Команды `discover --write` и `parent` заново сериализуют весь TOML-файл. Даже если изменяются только связи, комментарии и ручное форматирование теряются. Перед их использованием сохраните резервную копию `.git-lineage.toml` или добавьте файл в Git. Команда `init --force` перезаписывает существующую конфигурацию.

Параметры отчёта:

| Параметр | Действие |
| --- | --- |
| `--summary none` | Не выводить пояснения; предупреждения сохраняются |
| `--summary brief` | Вывести стандартный краткий набор пояснений |
| `--summary full` | Вывести все пояснения, автоматически выбранных родителей, ветки только из удалённых репозиториев и ветки вне дерева |
| `--format json` | Вывести машиночитаемый JSON вместо текста |
| `--color always` | Всегда использовать цвет; также доступны `auto` и `never` |
| `--ascii` | Использовать символы дерева из ASCII |
| `--all-remotes` | Расширить область отчёта ссылками из всех удалённых репозиториев |
| `--show-synced-remotes` | Показывать синхронизированные upstream-ссылки вместо их сворачивания |

Сам по себе `--all-remotes` не показывает все ссылки, существующие только в удалённых репозиториях. Чтобы включить их в отчёт, добавьте `--summary full` или задайте `show_remote_only = true`.

## Язык

По умолчанию интерфейс работает на английском. Посмотреть текущий язык или сохранить другой:

```console
git lineage language
git lineage language ru
git lineage language en
```

Выбор хранится в глобальной конфигурации Git под ключом `git-lineage.language`, поэтому действует во всех репозиториях и сохраняется после перезапуска терминала. Также доступен короткий псевдоним `lang`. Имена полей JSON и значения `kind` не зависят от языка. Текст самого интерфейса переводится на выбранный язык, а диагностика Git, операционной системы или библиотек разбора может сохранять свой язык.

## Конфигурация

Файл `.git-lineage.toml` необязателен. Явно заданные родители имеют приоритет над автоматическим определением.

```toml
version = 1
root = "main"
remote = "origin"
fetch = true

[parents]
dev = "main"
feature = "origin/dev"

[display]
collapse_synced_upstreams = true
show_remote_only = false
summary = "brief"
```

- `collapse_synced_upstreams` скрывает upstream-ссылку, если она указывает на тот же коммит, что и локальная ветка.
- `show_remote_only` включает ссылки удалённых репозиториев, даже если они не являются upstream-ссылками и не указаны явно в конфигурации.
- `summary` принимает значения `none`, `brief` и `full`.

Если короткое имя неоднозначно, используйте полное имя, например `refs/heads/dev`.

## Безопасность и изменения репозитория

`git-lineage` передаёт системному Git отдельные аргументы, не формируя командную строку для оболочки, и устанавливает `GIT_TERMINAL_PROMPT=0`. Утилита не просит Git выполнять `merge`, `rebase`, `reset`, `cherry-pick` или `push`. При этом системный Git может запускать настроенные пользователем вспомогательные программы для учётных данных и транспорта, а также SSH-команды.

По умолчанию перед отчётом выполняется `git fetch --prune`. Его точное действие зависит от конфигурации Git и правил `refspec` выбранного удалённого репозитория: Git записывает `FETCH_HEAD`, обновляет или удаляет настроенные ссылки, может автоматически получать теги и данные подмодулей, а также запускать обслуживание репозитория. Используйте `--no-fetch`, чтобы исключить эту сетевую операцию и связанные с ней изменения ссылок.

Команда построения отчёта не записывает `.git-lineage.toml`. Команды `init`, `discover --write` и `parent` изменяют этот файл, а `language` записывает `git-lineage.language` в глобальную конфигурацию Git.

Если `git fetch` завершился ошибкой, но сохранённых локально ссылок достаточно, построение отчёта продолжается с указанием на использование сохранённых данных. В JSON-режиме `stdout` остаётся машиночитаемым, а диагностика отправляется в `stderr`.

## Поддерживаемые платформы и инструменты

- Windows, Linux и macOS при сборке через Cargo
- Rust 1.85 или новее
- Системный Git, доступный через `PATH`
- `git-lineage`, доступный через `PATH`, для запуска в форме `git lineage`
